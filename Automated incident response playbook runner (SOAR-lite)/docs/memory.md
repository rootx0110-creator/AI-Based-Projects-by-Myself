# SOAR-Lite — Memory

Project memory: conventions, decisions, gotchas and context for future development. Read this before changing code.

## Conventions
- **Language/runtime:** CommonJS Node (`require`/`module.exports`), Node >= 18. No external packages — this is a hard constraint.
- **Persistence:** single JSON doc `data/soar.json`. Always write via `store.save()` (temp file + rename = atomic). Never hold references across `save()`.
- **IDs:** kebab prefixes — `pb_` (playbook), `inc_` (incident), `run_` (run), `evt_` (activity). Generated by `uid(prefix)` in `store.js`.
- **Timestamps:** ISO-8601 UTC strings via `store.now()`.
- **File layout:** `server.js` (routes), `lib/` (engine/store/reports), `public/` (CSS+JS+HTML), `docs/` (markdown rendered in UI), `data/` (runtime, gitignored except `.gitkeep`).
- **UI:** dark theme, CSS custom properties in `public/css/app.css`, ES-modules-free vanilla JS in `public/js/app.js`, templates via template literals.
- **API style:** REST-ish, always `{ data: ... }` or `{ error: ... }`, arrays returned as `data`.

## Decisions & rationale
- **Zero-dependency over convenience** — guarantees `node server.js` always runs; no install step, no supply chain surface. Anything needing a package (PDF export, SQLite) is deliberately deferred.
- **Simulated engine over mocked stubs** — `lib/engine.js` has a real async executor with sleep/branch/failure/retry semantics, so swapping in real connectors is behaviour-preserving.
- **HTML-first reports** — requirement; extra formats (JSON/MD/CSV) are near-free since the report model is already structured.
- **Auto-run matches playbooks by `trigger.severityMin`** (and optional `trigger.category`); incidents *can* still be handled manually.

## Gotchas
- On Windows, the project path contains spaces — always quote paths in scripts; `start.bat` uses `cd /d "%~dp0"`.
- `engine.startRun` is intentionally **fire-and-forget** (async closure persists runs); the HTTP handler must not `await` a full run, or requests would hang.
- Keep seeded historical runs consistent with `incidents` timestamps (report trend is date-based).
- The markdown renderer escapes HTML *before* adding inline formatting — do not re-escape rendered output or code spans break.
- Port is `8787`; override with `process.env.PORT`. `SOAR_NO_OPEN=1` disables auto-opening the browser.

## Context to preserve
- App identity: **SOAR-Lite** — Automated Incident Response Playbook Runner.
- Operational vocabulary: *playbook → run → step → incident → activity*. Use these terms consistently in UI text.
- Reports tab shows HTML as the first/default download option per the product requirement.
- Dashboard numbers must come from `GET /api/stats` (server-computed) so the client stays thin.
