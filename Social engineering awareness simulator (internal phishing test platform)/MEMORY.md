# MEMORY.md — SeaSim Project Memory

Purpose: give any future contributor (human or AI agent) instant context
on what SeaSim is, what exists, the decisions already taken, and the
next steps. Read this before changing anything.

---

## 1. What this project is

**SeaSim — Social Engineering Awareness Simulator.** A Windows desktop
GUI application (.exe) for *internal* phishing awareness programs:

- Security teams run **simulated** phishing campaigns against their own
  organization's staff.
- Measures susceptibility (open/click/report/dismiss rates).
- Delivers **just-in-time training** the moment someone interacts.
- **Ethical-by-design**: no real credential harvesting, no external
  targeting, mandatory consent workflow, localhost-only delivery.

Not a penetration-testing tool. It deliberately *cannot* capture
credentials — no password fields exist anywhere in the codebase.

## 2. Tech stack (final)

| Layer | Choice | Why |
|---|---|---|
| Language | Python 3.14 | available on the build host; stdlib-only app |
| GUI | Tkinter (Tk 9.0) | ships with Python → zero extra install for users |
| Persistence | single JSON file, atomic writes | inspectable, no DB dependency |
| Packaging | PyInstaller 6.22, onefile spec | one 12.7 MB `SeaSim.exe` |
| SMTP | hand-rolled loopback stub (`mailer.py`) | simulation only; never relays |
| Icon | generated by `build/icon.py` (pure stdlib PNG+ICO encoder) | no PIL dependency |

**No third-party runtime dependencies.** Everything is stdlib.

## 4. Decisions log (keep append-only)

- **Stdlib-only GUI.** Chosen so the exe needs no bundling surprises;
  custom widgets (stat tiles, chips, cards) emulate a modern design.
- **One JSON file** over SQLite: dataset is small (caps guarantee it),
  and operators can inspect/back up a single file.
- **Consent is engine-enforced, not UI-enforced**: `Engine.launch`
  refuses campaigns without `consent` + `policy_ack`; `assert_safe`
  double-checks. The wizard's step 7 and `ConsentDialog` both collect it.
- **Single JIT path**: JIT windows open only from `App._pump` after a
  `training` bus event. (Earlier double-path design caused duplicate
  windows; fixed.)
- **Built-in templates are read-only**; editing them offers duplication
  into a custom copy. Re-seeded by *name* after data reset.
- **Data minimization**: events store only status/timestamps/risk.
  No message bodies, no keystrokes, no credential fields.
- **`tk.Label` has no `style=` option** — all label styling is via
  explicit `bg/fg/font`. (A build-breaking bug we hit; don't regress.)

## 5. Verification status (as of this writing)

- `python -m compileall` — clean.
- Engine smoke tests (9/9 pass): consent block, consent launch, delivery
  thread, click scoring, report scoring, text report, program totals,
  external-host refusal, JSON round-trip, rate cap.
- GUI smoke tests (headless-ish, all pass): every view builds; campaign
  completes end-to-end; JIT `trained_at` recorded via pump; dismiss
  path; campaign detail/inbox/training/reports with data; SMTP stub
  roundtrip incl. restart; store reload.
- `dist/SeaSim.exe` (12.7 MB, PE32+ GUI) — launches and stays alive.

Re-run the GUI smoke test anytime with a temp data dir:

```bash
SEASIM_DATA_DIR=$(mktemp -d) python - <<'PY'
from seasim.app import App
app = App(); app.update()
for k in ["dashboard","campaigns","wizard","participants","templates",
          "inbox","training","reports","settings"]:
    app.navigate(k); app.update()
app.destroy(); print("OK")
PY
```

## 6. Known limits / next steps

- **macOS/Linux**: Tkinter code is portable, but the safety story (and
  the .exe target) is Windows-first; not tested there.
- **Persistence polish**: schema migrations are version-tagged but only
  v1→v2 fields exist; add real migration hooks if the schema grows.
- **Roadmap candidates**: per-department trend charts across campaigns,
  scheduled-campaign auto-prompt on dashboard (`due_campaigns` exists,
  UI wiring pending), reminder emails for non-responders
  (`non_responders` exists), localized JIT content.
- **Localization**: strings are English-only and hard-coded.

## 7. Style / conventions

- Module docstring on every file explaining its role.
- Dataclasses + `to_dict`/`from_dict` for anything persisted.
- UI reads/writes only through `ctx.store` / `ctx.engine`.
- Colors/fonts only from `seasim.ui.theme as T`.
- Engine→UI communication: `Engine.subscribe(kind, payload)`; kinds are
  `"delivery"`, `"status"`, `"training"`.
- Comment tone: explain *why* (especially safety decisions), not *what*.
